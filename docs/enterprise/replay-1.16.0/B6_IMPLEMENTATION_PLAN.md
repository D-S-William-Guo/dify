## 2. Official-first findings

### 2.1 可复用/必须保持的官方 1.16 能力

| 能力 | 官方依据 | B6 用法 |
| --- | --- | --- |
| 官方 compose 生成链 | `docker/docker-compose.yaml` 头注释“auto-generated by generate_docker_compose” | `docker/docker-compose.yaml` 与 `docker-compose-template.yaml` 均为只读；overlay 只覆盖最小字段 |
| API 四 runtime 同镜像 | `api`/`worker`/`worker_beat`/`api_websocket` 均 `image: langgenius/dify-api:1.16.0` | overlay 覆盖为同一企业 API image/tag，`api==worker==worker_beat==api_websocket` |
| Web 镜像 | `web: langgenius/dify-web:1.16.0` | overlay 覆盖为企业 Web image/tag（不等于 API tag） |
| Agent 两服务保持官方镜像 | `agent_backend: langgenius/dify-agent-backend:1.16.0`、`local_sandbox: langgenius/dify-agent-local-sandbox:1.16.0` | overlay **不得**覆盖这两个 service（镜像、env、depends_on、healthcheck、network 全部官方） |
| 依赖关系 | `api`/`worker` `depends_on.agent_backend`；`agent_backend` `depends_on.redis/plugin_daemon/local_sandbox` | overlay 不得移除这些依赖；合并后必须仍存在 |
| collaboration profile | `api_websocket.profiles: [collaboration]` | overlay 重声明 `api_websocket` 时显式保留 `profiles: [collaboration]` |
| 官方安全变量 | agent key fallback、`DIFY_AGENT_SERVER_SECRET_KEY`、Landlock、SSRF proxy、healthcheck、volume mount、`internal: true` 网络 | overlay 不覆盖任何 volume/network/healthcheck/安全变量 |
| 官方企业配置默认 | `api/configs/enterprise/__init__.py`：`ENTERPRISE_ENABLED=false`、`CAN_REPLACE_LOGO=false`（只读参考） | overlay 显式 `CAN_REPLACE_LOGO=true`，不改源码默认 |
| 官方登录配置 | `api/configs/feature/__init__.py` `LoginConfig`：`ALLOW_REGISTER=false`、`ALLOW_CREATE_WORKSPACE=false`、`PLATFORM_ADMIN_EMAILS=""` | overlay 显式传 `${ALLOW_REGISTER:-false}`/`${ALLOW_CREATE_WORKSPACE:-false}`/`${PLATFORM_ADMIN_EMAILS:-}` 保持企业默认与官方一致 |
| Web 前端系统特性 | `web/docker/entrypoint.sh` 把 `ALLOW_REGISTER`→`NEXT_PUBLIC_ALLOW_REGISTER`、`ALLOW_CREATE_WORKSPACE`→`NEXT_PUBLIC_ALLOW_CREATE_WORKSPACE` | overlay 在 `web` 服务同样注入 `ALLOW_REGISTER`/`ALLOW_CREATE_WORKSPACE`，保证前后端一致（E02 风险点） |
| 官方 Dockerfile | `api/Dockerfile` 与 `web/Dockerfile` 均声明 `ARG COMMIT_SHA`/`ENV COMMIT_SHA` | overlay `build:` 复用官方 Dockerfile，传 `COMMIT_SHA` build arg |

## 3. Overlay 契约（B6 唯一 product file）

### 3.1 文件：`docker/docker-compose.enterprise.yaml`

只允许此一个新文件。默认不需要新增 Dockerfile/构建元数据文件（官方 Dockerfile 已支持
`COMMIT_SHA` build arg）。Builder 若判断必须新增任何文件，必须停止并请求扩展 allowlist。

服务覆盖集合（只覆盖以下五个 service，且只覆盖下表字段；合并语义：
compose 对 mapping 键做 merge、list 键 append，官方 depends_on/healthcheck/volumes/networks/
其余 env 必须保留）：

| service | image（覆盖） | build（新增） | environment（追加/覆盖） | profiles（保留） |
| --- | --- | --- | --- | --- |
| `api` | `${DIFY_ENTERPRISE_API_IMAGE:-dify-api-enterprise}:${DIFY_ENTERPRISE_VERSION:-1.16.0-enterprise}` | `context: ..`，`dockerfile: api/Dockerfile`，`args.COMMIT_SHA=${DIFY_ENTERPRISE_VERSION:-1.16.0-enterprise}` | `ENTERPRISE_ENABLED=${ENTERPRISE_ENABLED:-false}`；`CAN_REPLACE_LOGO=true`；`PLATFORM_ADMIN_EMAILS=${PLATFORM_ADMIN_EMAILS:-}`；`ALLOW_REGISTER=${ALLOW_REGISTER:-false}`；`ALLOW_CREATE_WORKSPACE=${ALLOW_CREATE_WORKSPACE:-false}` | — |
| `worker` | 同 `api`（同一企业 API image/tag） | 同 `api` | 同 `api` | — |
| `worker_beat` | 同 `api`（同一企业 API image/tag） | 同 `api` | 同 `api` | — |
| `api_websocket` | 同 `api`（同一企业 API image/tag） | 同 `api` | 同 `api` | 显式保留 `[collaboration]` |
| `web` | `${DIFY_ENTERPRISE_WEB_IMAGE:-dify-web-enterprise}:${DIFY_ENTERPRISE_VERSION:-1.16.0-enterprise}` | `context: ..`，`dockerfile: web/Dockerfile`，`args.COMMIT_SHA=${DIFY_ENTERPRISE_VERSION:-1.16.0-enterprise}` | `ALLOW_REGISTER=${ALLOW_REGISTER:-false}`；`ALLOW_CREATE_WORKSPACE=${ALLOW_CREATE_WORKSPACE:-false}`（entrypoint 转 `NEXT_PUBLIC_ALLOW_REGISTER`/`NEXT_PUBLIC_ALLOW_CREATE_WORKSPACE`，保证前后端一致） | — |

注意：

- `api_websocket` 的 `profiles: [collaboration]` 必须显式出现在 overlay 的该 service 块内，
  不能依赖 merge 猜测；Phase E 用 `--profile collaboration config --services` 断言。
- overlay 的 `environment` 使用 mapping 追加，官方已有的 env（`MODE`、`INNER_API_KEY_FOR_PLUGIN`、
  `AGENT_BACKEND_*` 等）必须原样保留，不得删除或改写。
- `CAN_REPLACE_LOGO` 在 overlay 中写**字面 `true`**（官方源码默认 `false`，E08/E18），
  不允许默认回退到 false。
- 五个企业 runtime 的 image tag 统一来自 `DIFY_ENTERPRISE_VERSION`，默认 `1.16.0-enterprise`；
  `api`/`worker`/`worker_beat`/`api_websocket` 四个必须解析出**同一**企业 API image tag。

### 3.2 不覆盖（denylist 内 service 级保护）

以下 service 块 overlay 一律不出现，官方值原样生效：

- `agent_backend`（镜像、env、depends_on、network、retention 全官方）
- `local_sandbox`（镜像、env、healthcheck、Landlock 全官方；无 volume，也不得新增）
- `plugin_daemon`、`redis`、`db_postgres`、`db_mysql`、`sandbox`、`ssrf_proxy`、`nginx`、
  `weaviate` 及全部 vector store、`certbot`、`init_permissions`、`milvus` 相关、`oracle` 等

### 3.3 不得出现在 overlay 的内容

- 官方 volume/network/healthcheck/安全变量的任何覆盖（校验方式见 §6）。
- `local_sandbox` 的永久共享 volume；`agent_backend` 的任何新 volume。
- 任何真实 secret 或把 `DIFY_AGENT_SERVER_SECRET_KEY` 的官方开发默认
  `MDEyMzQ1Njc4OWFiY2RlZjAxMjM0NTY3ODlhYmNkZWY` 显式写入 overlay。
- 旧 1.15 遗留变量：`HOME_OVERRIDE`、`DIFY_INTERNAL_API_URL`。
- 对 `agent_backend` `DIFY_AGENT_INNER_API_KEY` 的单独覆盖（必须保持官方 fallback 链，
  使展开后与 `api` 的 `INNER_API_KEY_FOR_PLUGIN` 相等）。
- 对 `DIFY_AGENT_RUN_RETENTION_SECONDS` 的覆盖（官方默认 259200，保留）。
- 对 `DIFY_AGENT_REDIS_URL` 的覆盖（官方默认 database `/2`，保留）。

## 10. Risks, decisions and stop conditions

### 10.1 Known limitations

- Compose 多文件 merge 对 `profiles`/`depends_on` 依赖 compose 版本行为；已用
  `--profile collaboration config --services` 与 depends_on 断言兜底，但 build/recreate 行为
  属于 Phase F（NOT_RUN），静态结果不替代运行验证。
- image tag 相同不能代替 image ID 相等；Phase F 的 `docker inspect .Image` 断言延后到另行授权阶段。
- `ENTERPRISE_ENABLED` 默认 `false`：企业 overlay 默认不启用企业特性，与旧 1.15 默认一致；
  真正启用由部署 `.env` 显式设置。B6 不改变此默认。
- `CAN_REPLACE_LOGO=true` 只是把配置值放开，logo 替换 UI 行为依赖前端企业 Web 构建，B6 不验证。

### 10.2 RECORDED_DECISION

1. `B9_KEEPS_DEFER`：B9 产品契约文件不存在，保持 DEFER；B6 不产出 B9 文档、不预授权 B10。
2. `B6_SINGLE_FILE_OVERLAY`：product allowlist 默认仅
   `docker/docker-compose.enterprise.yaml`；官方 Dockerfile 复用，不新增 Dockerfile/build 元数据文件。
3. `B6_PHASE_E_ONLY`：Phase F 及后续运行验证默认 `NOT_RUN`，需协调者另行授权。
4. `CAN_REPLACE_LOGO_OFFICIAL_FALSE`：官方默认 `false` 不变；overlay 显式 `true`。
5. `AGENT_OFFICIAL_IMAGES`：`agent_backend`/`local_sandbox` 保持官方 1.16 镜像与全部安全边界。
6. `NO_PERMANENT_SANDBOX_VOLUME`：overlay 不新增 local_sandbox 永久共享 volume。

### 10.3 Stop conditions

- exact branch/SHA/clean/B5 ancestor 不符；
- 修改了 `docker/docker-compose.yaml`、`docker/volumes/**`、`docker/envs/**` 或任何 denylist 文件；
- 需要新增 overlay 之外的文件而未获批准；
- `config -q` 失败，或 `--profile collaboration config --services` 不含 `api_websocket`；
- `api`/`worker`/`worker_beat`/`api_websocket` 未解析为同一企业 API tag，或 `web` 不是企业 Web tag；
- `agent_backend`/`local_sandbox` 镜像被覆盖，或其 depends_on/healthcheck/volume/network 被改动；
- `api`/`worker` 失去 `agent_backend` 依赖，或 `agent_backend` 失去 redis/plugin_daemon/local_sandbox 依赖；
- 官方 profile 丢失；
- key 相等断言失败、Redis database 编号冲突、`CAN_REPLACE_LOGO` 展开值不符合 §5；
- overlay 覆盖官方 volume/network/healthcheck/安全变量，或出现 secret/开发默认 key；
- Phase F 被擅自执行；
- 出现 P0/P1 security、key、Landlock、sandbox 隔离或 profile 泄漏。
